# B3 dashboard projection contract

The opt-in `projection=app_api_value_v1` uses the existing authenticated v1 usage routes. Requests without it retain their existing shape and selection. A frozen context inherits its projection; changing it on an existing/derived context is rejected. The projection freezes `desktop-primary-models-v1`: Codex `gpt-6.1-sol`, Claude `claude-opus-5-5`, as provider/model pairs applied to accepted events before aggregation. These filters make full-month fee comparisons ineligible. Stored events, valuations and index schema are unchanged.

Projected envelopes include a `projection` descriptor with unit, exact USD-per-credit definition, primary-model policy/pairs and the committed USD valuation policy. Every projected usage summary includes `app_credits` (unit, amount, USD-per-credit); null, zero and partial coverage retain the accompanying authoritative USD coverage. Event values expose the same normalization. Arithmetic stays in Python, with the existing bounded Decimal context and no additional internal rounding.

Projected Overview includes `analysis`: complete-query model/project distributions for tokens, USD and app credits, and a methodology projection. Each distribution is at most twelve slices: eleven explicit groups plus Other, ranked by the selected metric with stable IDs. Shares use six fractional percentage places with a residual on the last nonzero slice, summing to 100. Empty/unpriced/covered-zero have no percentages. Partial monetary denominators are explicitly priced subtotals; token distributions retain unpriced tokens. All financial quantities and shares are strings; the browser may convert them only for geometry.

Methodology exposes five category counts, priced-category counts, exact unrounded priced contributions, mixed/unknown rates and aggregate rounding adjustment. Missing provenance makes contributions unavailable; unpriced event charges are never presented as part of the priced subtotal. The sum of available contributions plus adjustment equals authoritative USD. Reasoning remains a nullable output subset. Existing rate provenance groups remain bounded to eight. `/usage/analysis` pages these groups with signed context-bound cursors, default/max page size eight; every page repeats the whole-query distributions, methodology totals and summary. Paging cannot narrow headlines or denominators. Maximum response remains 8 MiB; existing event/query work bounds apply.

Overview also supplies `analysis_pagination` for the included first eight rate groups. Initial Explore reuses that validated analysis and continuation under the same context; it fetches `/usage/analysis` only for later pages. A one-row projected project response can capture a broad clock context before deriving a filtered query; that row/page is never used as the dashboard headline or pie denominator. This avoids computing a full unused broad Overview and then requesting its analysis twice.

Performance refinements preserve calculation semantics: immutable USD catalogs precompute exact rate selections without changing stored payloads/versions; bounded metadata-text validation is memoized. Every event's credit valuation still validates tokens, reasoning and amount. Since those amounts/counters are nonnegative and Decimal precision covers the documented bounds, aggregate overflow validation once at the end is equivalent to checking each monotone prefix; no extra rounding or clipping is introduced. Late-overflow, mixed-unit/version and exact reconciliation tests remain required.

Pure per-event normalization and selected-rate explanations each have a 4,096-entry bound. Keys include the complete immutable valuation (and selected rate for explanations); repricing or fact changes produce different keys. Catalog provenance is checked before explanation reuse. These are mathematical memoizations, not stored HTTP responses: snapshot/publication validation and failed-read behavior remain unchanged. The derived catalog lookup is excluded from dataclass/wire serialization, and immutable catalog copies retain their supported behavior.

Schema and frontend validation must reject malformed exact strings, oversized groups/shares, inconsistent units and altered policy descriptors. Default legacy fixture responses remain valid and unchanged. Frozen publication/version/cursor rules, read failures, explicit Update view, privacy projections and offline reads retain the S12 contract.


October 27 average-axis follow-up (0.16.5): projected analysis now emits optional `daily_average` metadata: `calendar_days` (0–32), basis `selected_calendar_days_including_empty`, rounding `half_even_18_decimal_places`, and nullable nonnegative exact decimal strings `tokens_per_day`, `usd_per_day`, `app_credits_per_day`. These are derived display means of the full authoritative filtered summary, calculated in Python, rounded half-even to 18 fractional places. They do not revalue events or change stored amounts. Calendar-day counts include empty dates and partial endpoint days under the frozen named zone; a selected day uses one, and an empty interval uses zero. Empty queries have null amounts, unpriced money remains null, partial money means the priced subtotal, and genuine zero stays zero. Overview and every analysis page repeat the same frozen values; history paging cannot change them. Older payloads without this optional metadata remain accepted by the current client; malformed present metadata is rejected. The published schema, browser mirror and captured fixtures are updated together. Default non-projected responses remain unchanged.


### Explicit empty checkbox selections

Repeated optional `empty_selection=project_id|model|effort` parameters mark explicitly deselected dimensions. Ordinary omitted/empty model/project/effort lists keep their existing unrestricted meaning; the dashboard sends repeated values for a selected subset. Frozen `applied_filters.empty_selection` is present only when nonempty (at most three supported names), preserving ordinary response shapes. Any such dimension matches no events through the headless `UsageFilters.match_none` flag, so summaries, charts, analysis, history and means stay coherent and empty. No fictitious model/project identifiers or browser-reconstructed totals are used.

Facets omit their own value filter as before and ignore empty-selection flags while enumerating recoverable choices; other chosen values, provider, primary-model policy, time/day and search still constrain them. Exact query identity, cursors, related-response validation and failure retention include empty selections. The current client validates the optional extension; older clients using their strict schema may reject an explicit-empty response. No database migration or read-side import is involved.
