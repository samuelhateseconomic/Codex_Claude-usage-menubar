## Data and navigation decisions

- [v1-schema.js](../windows/dashboard/v1-schema.js) mirrors [the published schema](api/usage-hub-v1.schema.json); tests enforce exact parity. [v1-client.js](../windows/dashboard/v1-client.js) validates the published envelope, dictionary issue counts, exact strings, real mode, requested context/detail identity, response byte limits and event pricing version. It uses fixed safe error messages, same-origin cookies and an in-memory CSRF token for explicit mutations. The bounded validator supports only the schema's current vocabulary; it is not a general JSON Schema engine.
- The earlier candidate modules/fixtures remain historical preparation and are not imported by the real dashboard. Published S12 response kinds, `data` nesting, `real` mode, `events` sort, `configuration_changed` conflict code and field names are authoritative.
- [local-session.js](../windows/dashboard/local-session.js) captures one **unfiltered frozen base** per preset/timezone/publication, then derives the complete current metadata/provider/day selection from that base. This handles S12's omitted-field inheritance correctly: clearing a filter returns to the unfiltered base without silently retaining the old filter or advancing time. A preset/timezone change or explicit Refresh view captures a new base. Changing preset also clears a selected day.
- Overview, matching list/facets or conversation/events are published as one coherent context/range/version/filter bundle. Full-result headlines come from the backend; pages are never summed. Detail/event full matched summaries must agree. Status and live limits are separately current cached service state. Source/counter coverage is report-wide, independently of matched conversation pricing coverage.
- Opaque cursor stacks, sort/page size, parent filters, captured context, scroll position and opener identity survive detail/Back and native browser history. Reload resumes authentication and the history entry's cursor. These metadata snapshots use browser history only; no credential is stored there. Pagination changes do not recapture the clock. UI paging uses default 50, with 1/25/50/100 selectable; one row is useful for small-data inspection and acceptance.
- Obsolete successes/errors cannot replace newer navigation. Loading removes old interactive rows. Failed requested filters restore the last accepted result and its original controls, with Retry retaining the requested selection. One 409 `context_expired`/`revision_changed` retries the entire bundle from a fresh base, discarding obsolete cursors and detail return context. A repeated conflict or ordinary failure stops; no rescan or provider polling is implied.
- Native Back and keyboard Escape restore the list; explicit Back also restores its opener focus and scroll. Search debounce is cancelled on navigation. Modal focus is preserved. Both chart metrics retain the exact reviewed formatting, zero baseline and matched-column scale; numeric conversion is solely approximate SVG geometry/ticks. Zero/unpriced days have a transparent keyboard/click target.
- Fee/timezone settings use a typed draft, explicit Save/Cancel/Reload and the loaded expected configuration version. Blank fee means null; zero remains zero. On `configuration_changed`, the draft is retained and the user is told to reload. Only fee/timezone fields are patched; existing native roots, rates and report settings are preserved and their native editing limitation is explicit.
- Rescan submits the documented local import job. Settings saves may queue repricing. Explicit bounded job reads stop after 30 attempts, at a terminal state or cancellation. Pending, failed and succeeded outcomes stay distinct. Only successful publication triggers a coherent query refresh; a failed follow-up view cannot announce a refreshed view. Opening Limits reads cached active-account data only and never polls providers.
